# 🚀 API Execution & Database Behavior Documentation Skill

When onboarding to any new software project or codebase, understanding how requests flow through microservices and mutate database/cache state is critical. This skill provides a standardized framework for documenting any API endpoint end-to-end.

---

## 📋 Standard API Documentation Checklist

For every API endpoint in a project, create a document containing the following 6 mandatory sections:

### 1. 🌐 API Metadata & Request Payload
- **HTTP Method & Path**: e.g., `POST /api/orders`
- **Target Service & Port**: e.g., `API Gateway:8080` ➔ `Order Service:8081`
- **Authentication / Authorization Headers**: e.g., `Authorization: Bearer <AccessToken>`
- **Request Body JSON**: Complete sample payload

### 2. 🗺️ Network Traversal & Microservice Flow
Trace the complete architectural path step-by-step:
```
Client ➔ Gateway (Port) ➔ Global Filters (JWT/Cors) ➔ Service Registry (Eureka/K8s) ➔ Controller ➔ Service Layer ➔ Inter-Service Calls (Feign/gRPC) ➔ DB/Cache/Kafka
```

### 3. 🧑‍💻 Code File & Line Traversal Trace
Provide exact file links and line numbers for every class executed in the call chain:
- **Filter**: `SecurityFilter.java#L40-L75`
- **Controller**: `OrderController.java#L34-L41`
- **Service**: `SagaOrchestrator.java#L47-L135`
- **Repository / Feign Client**: `InventoryClient.java#L12-L16`

### 4. 🗄️ Database State (MySQL / PostgreSQL / MongoDB) BEFORE vs AFTER
Document exact database table states and executed SQL queries:
- **Database Tables**: Schema names and affected tables.
- **State BEFORE**: Pre-execution row values.
- **SQL Queries Executed**: Exact `SELECT`, `INSERT`, `UPDATE`, `DELETE` statements generated by ORM (Hibernate/JPA).
- **State AFTER**: Post-execution row values, generated primary keys, and timestamps.

### 5. ⚡ Cache (Redis) & Messaging (Kafka / RabbitMQ) Behavior
- **Redis Cache**: Hits, Misses, Keys set (`SET lock:sku NX PX`), or cache eviction (`DEL catalog:products`).
- **Kafka Topics**: Topic name (`order-events-topic`), payload appended, consumer groups listening.

### 6. 📤 Response Payload & HTTP Status Code
- **HTTP Status**: `200 OK`, `201 Created`, `400 Bad Request`, `401 Unauthorized`
- **Response JSON Body**: Exact JSON output returned to the client.

---

## 💡 Quick Onboarding Workflow

When onboarding to a new project:
1. Run local infrastructure (`docker-compose up -d`).
2. Run automated test suite or trigger APIs via Postman / curl.
3. Capture ORM SQL logs (`spring.jpa.show-sql=true`).
4. Generate an API Execution & DB Behavior document for each endpoint using this template.
